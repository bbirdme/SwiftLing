# Contributing to SwiftLing

Thank you for helping. Everyone can report a bug, suggest an idea or send a change. Only the maintainer merges changes into `main`.

## Report a bug or suggest an idea

Open an [issue](../../issues/new/choose). A good report says:

- what you did, what you expected and what happened;
- your WordPress and PHP versions and the plugins and theme you use;
- the texts of **Logs › Copy for support** in SwiftLing (it holds no content, keys or passwords, and you can read it before you send it).

For a question or an open idea, use [Discussions](../../discussions).

## Send a change

1. Fork the repository and make a branch from `main`.
2. Make your change. Keep it to one thing, and match the code around it.
3. Run the checks (see the README): `composer lint` and `composer test`. A bug fix comes with a test that fails without it.
4. Open a pull request and say what it changes and why.

The maintainer reviews every pull request and may ask for changes. Checks run on GitHub for first-time contributors only after the maintainer approves them.

## Security

Do not report a vulnerability in a public issue. See [SECURITY.md](SECURITY.md).
